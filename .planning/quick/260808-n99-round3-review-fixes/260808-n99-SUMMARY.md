## Accomplishments

- `getOrCreateStagedPath` now reports the staged-path requirement in the same unit it enforces (`len(state.paths)+1`, total paths), so raising `MaxStagedPaths` always raises the reported requirement — fixed the one case (container-companion transformer) where the old visible-path formula under-reported by 2.
- Soft-skip Info logging for companion representations moved from the staging site to the post-merge fold point in `commitStagedPaths`, so a document that is later rejected or never committed never logs a skip while `NumSoftSkippedRepresentations()` stays 0 — verified with a logger-backed test on both paths.
- `newIngestErrorString` panics if a resource-layer `IngestError` is constructed with a non-empty value, enforcing the documented `Value()==""` contract for resource failures as a programming-bug guard.
- `simd_docs_guard_test.go`'s cold-cache fallback no longer references a deleted `knownSIMDLoadingSource` helper; it now emits an honest `t.Skipf` naming `go mod download`, or `t.Fatalf` under `AMI_GIN_REQUIRE_SIMD_DOCS_UPSTREAM=1`.
- New tagged test `TestSIMDParserBudgetRejectsLexicalOrderPath` pins that the SIMD adapter's object-key walk order is lexical, not document order; empirically confirmed to fail when `parser_simd.go:235`'s `sort.Strings(keys)` was temporarily reversed, then confirmed to pass again after revert (reversed state never committed).
- `gin-index build` now accepts `--max-staged-paths`, mirroring `gin-index experiment`'s validation (`< 0` rejected) and `WithMaxStagedPaths` wiring.
- `WithMaxStagedPaths`/`Path()` godoc, `remapCompanionIngestErrorPath`'s comment, `CLAUDE.md`'s companion-staging ordering claim, `docs/simd-deployment.md`'s stale "Phase 22" wording and missing `WithMaxStagedPaths` cross-reference, `SECURITY.md`'s T18-06/T18-11/T18-12 evidence cells, and `CHANGELOG.md`'s `MaxStagedPaths` bullet are all corrected.

- Kept the relocated soft-skip Info log limited to the 3 frozen INFO-level attrs (`operation`, `status`, `error.type`) rather than adding `alias`/`rgID`, per the documented `logging/doc.go` INFO-level allowlist invariant. - The Task 2 mutation check used `sort.Sort(sort.Reverse(sort.StringSlice(keys)))` (full reverse) rather than a document-order-specific mutation. Under this reversal the test failed by rejecting `$.a` instead of the expected `$.z` (not `$.m` as the plan's illustrative text guessed for a hypothetical document-order run) — this still proves the test is sensitive to traversal order, which is the property the mutation check exists to verify.
