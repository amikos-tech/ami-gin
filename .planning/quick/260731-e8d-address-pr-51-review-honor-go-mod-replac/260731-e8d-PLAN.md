<objective>
Fix two PR #51 review findings on branch `chore/notice-version-guard`: CI's simd-parser job
ignores `go.mod` `replace` directives when picking which pure-simdjson release to fetch, and
`notice_version_guard_test.go` hardcodes `v0.1.7` in five places, so a routine dependency bump
silently breaks 4 of 6 subtests while the guard itself stays correct.

Purpose: Close the exact maintenance hazard PR #51 was created to eliminate — a NOTICE/version
guard whose own test suite requires manual upkeep on every bump.

Output: `.github/workflows/ci.yml` simd-parser job mirrors the Makefile's replace-aware version
template; `notice_version_guard_test.go` derives the effective pure-simdjson version once via
`go list -m` and uses a synthetic sentinel version for the "different version" fixture, with zero
hardcoded version literals remaining.
</objective>

<verified_facts>
Established during planning — do not re-derive:

1. `Makefile:97` already computes the effective version correctly:
   `go list -m -f '{{if .Replace}}replacement{{else}}requirement{{end}}:{{with .Replace}}{{.Version}}{{else}}{{.Version}}{{end}}' github.com/amikos-tech/pure-simdjson`.
   The simpler template needed here (no "replacement:"/"requirement:" prefix, just the version
   string) is `{{if .Replace}}{{.Replace.Version}}{{else}}{{.Version}}{{end}}`.

2. `ci.yml:116` currently reads:
   `pure_simdjson_version="$(go list -m -f '{{.Version}}' github.com/amikos-tech/pure-simdjson)"`
   — this ignores `.Replace` entirely. It is the ONLY line that needs to change in that job.

3. Under a local path `replace` (`=> ./some-dir`), the fixed template yields an empty string,
   making the next line fail with a cryptic module-query error. This is ACCEPTED and INTENTIONAL
   — do not add a guard/validation branch in ci.yml for this. A local, unpublished module has no
   release binary to fetch; failing loudly is correct.

4. go.mod currently requires `github.com/amikos-tech/pure-simdjson v0.1.7` with no active
   `replace` directive, so the effective version equals the required version today.

5. `go list -m -f '{{if .Replace}}{{.Replace.Version}}{{else}}{{.Version}}{{end}}' ...` does NOT
   fetch or validate that the replacement version exists upstream — it only resolves the
   directive text. Verified empirically: the existing test already relies on this with the
   non-existent tag `v0.1.8` (latest published is `v0.1.7`). A synthetic sentinel like `v9.9.9`
   works identically.

6. `pureSIMDJSONModule` (`notice_version_guard_test.go:14`) is deliberately split as
   `"github.com/amikos-tech/" + "pure-simdjson"` so `make simd-isolation-check` (which greps for
   the exact contiguous quoted string) does not flag this test file. Any new code must keep using
   this constant — never write the module path as one contiguous string literal.

7. `copyNoticeGuardInputs` (`notice_version_guard_test.go:80`) currently returns only `dir string`
   and is called from 5 of 6 subtests (all but `CI runs the dedicated guard before golangci-lint`,
   which reads `ci.yml` directly and needs no version).
</verified_facts>
