<objective>
Add a `TypeBigInt` case to both element-handling switches in the pure-simdjson adapter (`parser_simd.go`) so out-of-range integers (values that overflow both int64 and uint64) route through the same numeric failure policy as the stdlib parser, instead of falling into the fail-closed `default:` arm and surfacing as a parser-layer error. Also bump the stale native-library bootstrap version pin in the SIMD CI job so it fetches a native binary matching the already-bumped v0.1.7 Go bindings.

Purpose: pure-simdjson v0.1.7 (already pulled in via dependabot PR #48) introduced `TypeBigInt` (element.go:39-40) for integers outside int64/uint64 range, which v0.1.4 did not have. The adapter's type switches predate this element kind and silently mis-route it, breaking numeric-failure-policy parity between the SIMD and stdlib parsers and failing `TestSIMDParserNativeNumericFailuresUseNumericPolicy` in CI.
Output: `parser_simd.go` handles `TypeBigInt` correctly in both `walkElement` and `materializeElement`; `.github/workflows/ci.yml` SIMD job bootstraps the correct native library version. `TestSIMDParserNativeNumericFailuresUseNumericPolicy` passes in CI (native library unavailable locally — see task 1 verify note).
</objective>
