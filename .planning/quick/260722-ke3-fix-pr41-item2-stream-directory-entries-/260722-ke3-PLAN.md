# Quick Task: Stream external corpus directory entries

## Problem

PR #41 review item 2: `phase20ExternalBenchmarkPaths` (`benchmark_test.go`) calls
`os.ReadDir(directory)`, which reads and sorts the *entire* directory listing into
memory before the 64-file cap is enforced. A directory with thousands of entries
allocates all of them up front, even though the loader only ever accepts 64
supported files.

## Fix

Replace `os.ReadDir` with `os.Open` + streaming `File.ReadDir(n)` batches:

- Read entries in bounded batches (`phase20ExternalReadDirBatch = 128`).
- Reject early the moment supported files exceed `phase20MaxExternalFiles`, before
  reading the rest of the directory.
- Keep the explicit `sort.Strings(paths)` on the success path — `File.ReadDir` does
  not sort, so deterministic ordering is preserved by the existing sort.

### Behavior change

Early-exit rejection no longer reports the exact file count (we stop at 65), so the
error message becomes "contains more than %d supported files". The `file-count`
test asserts only `err != nil`, so it is unaffected.
