## Narrative Findings (AI reviewer)

### Critical Issues

#### CR-01: A document-close failure can silently discard the remainder of an ingest run

**Classification:** BLOCKER

**File:** `parser_simd.go:42-51`

**Issue:** `Doc.Close` is allowed to fail. In `pure-simdjson` v0.1.4, that failure leaves the document open and does not clear the owning parser's live-document handle, so the reusable parser remains busy. This adapter returns the close failure as an ordinary `Parse` error. `GINBuilder.AddDocument` therefore applies `ParserFailureMode`; in soft mode it returns `nil` and drops the document, and every later call receives `ErrParserBusy` and is silently dropped too. One native cleanup fault can consequently turn the rest of a build into unreported data loss.

The combined-error branch has a second correctness defect: when walking already returned a tagged sink error, it wraps `closeErr` and interpolates the original `err` with `%v`. The sink error is no longer in the unwrap chain, so numeric, transformer, or schema provenance is lost and the wrong failure-mode knob/layer is applied.

**Fix:** Introduce a dedicated fatal parser-lifecycle error that unwraps the original walk error, have `AddDocument` recognize it before applying parser soft mode, store it as the builder's tragic error, and reject all later calls hard. Preserve the walk error as the wrapped cause when both operations fail. For example:

```go
defer func() {
	closeErr := doc.Close()
	if closeErr == nil {
		return
	}

	combined := errors.Wrap(closeErr, "close pure-simdjson document")
	if err != nil {
		// Keep stageCallbackError / softSkipDocumentError in the unwrap chain.
		combined = errors.Wrapf(err, "walk failed and document close also failed: %v", closeErr)
	}
	err = &fatalParserLifecycleError{err: combined}
}()
```

`AddDocument` must detect `fatalParserLifecycleError`, set `b.tragicErr`, and return it without consulting `ParserFailureMode`.

### Warnings

#### WR-01: The public adapter cannot release its native parser deterministically

**Classification:** WARNING

**Files:** `parser_simd.go:19-35`, `README.md:96-107`, `docs/simd-deployment.md:44-55`

**Issue:** `pure-simdjson` documents explicit `Parser.Close` as the primary cleanup path, but `NewSIMDParser` returns the base `Parser` interface, which has no `Close`, and the concrete wrapper is private. Callers therefore cannot release the native parser handle after finalizing a builder; cleanup is deferred to a GC finalizer. The documented helpers also return only the builder, permanently losing any potential cleanup handle. Repeated builder/parser creation in a long-running process can retain native handles and library state for an unbounded period until GC happens to run.

**Fix:** Expose an owned closeable adapter, for example an exported interface that embeds both `Parser` and `Close() error`, return it from `NewSIMDParser`, and document who owns it and when it must be closed. Update examples to retain the closeable value until all `AddDocument` calls finish, or make `GINBuilder` own and close parser resources through an explicit lifecycle API.

#### WR-02: Element type inspection discards actionable native errors

**Classification:** WARNING

**Files:** `parser_simd.go:73`, `parser_simd.go:164`

**Issue:** Both traversal paths call `Element.Type()`. That upstream convenience method deliberately collapses `ErrClosed`, `ErrInvalidHandle`, `ErrPrecisionLoss`, native panic errors, and other failures to `TypeInvalid`. The adapter then creates a generic error, breaking `errors.Is`/`errors.As` and losing the native cause needed to diagnose ABI, lifecycle, or FFI failures.

**Fix:** Use `TypeErr()` in both functions and wrap its returned error with path context; reserve the generic `TypeInvalid` message for the case where `TypeErr` succeeds but reports an invalid kind.

```go
elementType, typeErr := element.TypeErr()
if typeErr != nil {
	return errors.Wrapf(typeErr, "read pure-simdjson element type at %s", canonicalPath)
}
```

#### WR-03: The SIMD-named tests never construct or execute the SIMD adapter

**Classification:** WARNING

**Files:** `parser_simd_test.go:1-303`, `parser_parity_fixtures_test.go:23-31`

**Issue:** `parser_simd_test.go` has no `simdjson` build constraint and tests only `typedSinkTestParser`; it never calls `NewSIMDParser`, `simdParser.Parse`, `walkElement`, or `materializeElement`. Likewise, the `simd-numeric-parity` golden is generated and asserted through the default stdlib parser. As a result, `go test -tags simdjson ./...` passing proves that the adapter compiles, not that it parses a document correctly, preserves parity, closes documents, or routes failures correctly.

**Fix:** Add tagged tests that load a controlled native test artifact, construct `NewSIMDParser`, and compare real SIMD output with stdlib/goldens for scalars, exact integers, whole/exponent floats, nested objects and arrays, empty containers, duplicate keys, Unicode, and transformed subtrees. Add injectable native parser/document seams so close failures and accessor/iterator errors can be tested without depending on an actual FFI fault. The tagged CI job should fail, not silently skip, when its configured native artifact is absent.

#### WR-04: The isolation and tagged quality gates are not enforced by normal automation

**Classification:** WARNING

**File:** `Makefile:3-90`

**Issue:** `simd-isolation-check` is a standalone target: `build`, `test`, `integration-test`, `lint`, and `security-scan` do not depend on it, and the repository CI does not invoke it. The target itself runs only default `go build` and `go vet`; the normal tests, vet, and vulnerability scan likewise omit `-tags simdjson`. A future untagged import or tagged-only compile/security regression can therefore pass every required project target and CI job.

**Fix:** Wire the isolation check into a required CI/build dependency and add an explicit tagged gate, for example `go test -tags simdjson ./...`, `go vet -tags simdjson ./...`, and `govulncheck -tags simdjson ./...`, with the controlled native setup required by WR-03. Keep the default dependency-graph assertion as a separate step so tagged verification cannot mask accidental default inclusion.
